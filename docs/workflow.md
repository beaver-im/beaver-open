# 第13章　开发闭环、验证命令与评审清单

最后核验：2026-11-25（Asia/Shanghai）。这是全仓长期执行标准。

最高原则：开源不运营，无历史包袱，不写/不留任何兼容代码，不因实现成本或改动面大妥协；发现问题直接整改，不需要的直接删除，并同步更新所有受影响调用方。

## 从任务到交付

1. **定位**：记录目标/非目标/验收；`git status --short`、`git diff`、`git diff --cached` 区分现有修改。不要恢复或暂存别人的文件。
2. **按需读取**：从[模块导航](modules/README.md)找到责任域，检索符号/接口并读局部源码；边界不清才扩大范围。
3. **实现**：先确认契约与副作用；接口字段变化同时改类型、API、页面与文档；文件改名同步全部引用。
4. **验证**：选最小充分检查集；先只读检查，再按需构建。记录实际命令、工作目录、结果与限制。
5. **更新知识**：职责/入口/接口/命令变了，更新相应页面；结构性选择写 ADR，临时进度进任务卡。
6. **交接**：未完成时按[模板](tasks/TEMPLATE.md)写下一步；完成时交付证据。无复杂待办的微小任务可用最终交付说明，不强制新建任务卡。

## 命令事实源

根 [package.json](../package.json) 是脚本事实源，依赖须已就绪。下表命令均从仓库根执行。

| 变更面 | 命令 / 核验 | 范围与限制 |
| --- | --- | --- |
| 纯文档/命名 | `node scripts/check-knowledge.mjs`；`git diff --check` | 只读；检查链接、章节、脚本名、路径与 `src` 命名，不证明业务正确 |
| TS/Vue 类型 | `node_modules/.bin/vue-tsc --noEmit -p tsconfig.app.json` | 只读；仓库可能存在基线错误，需区分本次新增 |
| 单文件 lint | `node_modules/.bin/eslint <file>` | 不加 `--fix`；只读验收 |
| 测试构建 | `npm run build_test` | Vite 构建，会写 `dist`；不等于行为测试 |
| 生产构建 | `npm run build_prod` | 会写 `dist`；普通任务不默认跑生产发布流程 |
| 本地开发 | `npm run dev` | 启动开发服务器（4012）；使用授权配置，不记录令牌 |
| 根 lint 自动修复 | `npm run lint` | `eslint . --fix`，会批量改文件；不能当只读验收 |
| 版权头 | `npm run add-copyright-header` | 会批量改文件；新文件按既有头模板补齐 |

根清单没有 `test` 脚本，也没有统一覆盖率门槛。不能执行不存在的命令后说“测试完成”；新增自动化测试时把真实命令加入本表和 [knowledge-checks.json](knowledge-checks.json)。

## 命名与契约验收

- `node scripts/check-knowledge.mjs` 会检查：`src` 下除 `App.vue` 外没有大写开头文件、没有连字符/下划线文件名或目录名。
- CSS 类名里的 kebab-case 不触发命名失败；只检查文件名与目录名。
- 文件改名后手工确认：router 动态 import、组件 import、资源 `import`、文档链接都已更新；不保留旧路径别名。
- 接口字段变化后确认：`I...Req/Res`、`...Api`、页面读写与文档一致；没有旧字段映射或空占位。
- 编排变化后确认：`configDetail.type` 与 `runtime` 一致，提示词键为 snake_case，`knowledgeIds` 未被提交。

## 风险导向验收

- 登录态：Token 注入、OAuth 回调清理、认证失败跳转、路由守卫覆盖。
- 接口：合法/非法参数、`code !== 0`、超时、失败态展示。
- 凭据：明文只出现一次，展示后清空，未落 Pinia/localStorage/URL/日志。
- 编排：草稿态创建、`router.replace` 后配置不丢、整份提交不覆盖其他分区。
- Vue 页面：空/加载/失败、快速切换竞态、弹窗草稿清理、销毁时释放监听。
- 破坏性操作：删除/停用/重置密钥有二次确认，结果以服务端返回为准。

## 证据格式与完成标准

每次交付说明：变更文件/行为 → 运行的命令与目录 → exit/关键结果 → 未运行及原因 → 剩余风险。
区分既有基线问题与本次新增；没有运行的检查不能标通过。
只有验收满足、知识同步且无误覆盖现有工作才称完成。
