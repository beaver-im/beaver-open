# 第15章　任务交接与归档

这里放临时执行上下文，不把正在做什么塞进架构页，也不复制整段聊天或代码。当前目录提供规范与模板，不代表已有任何业务任务完成。

## 创建与生命周期

- 复杂、多会话或需要他人接手时，从 [TEMPLATE.md](TEMPLATE.md) 建 `active/YYYY-MM-DD-short-name.md`。
- `active/` 与 `completed/` 目录在首次出现真实任务时创建，不用虚构任务填满目录。
- 一张卡对应一个目标，写目标/非目标、分支与基线、已核实路径、进度、验证、阻塞、下一步。
- 小变更可直接在交付说明留同等证据，不强制每次写任务文档。
- 活动状态：进行中 / 阻塞 / 待验证；完成须满足[工作流](../workflow.md)，再移动到 `completed/YYYY/`。
- 归档写明完成/放弃原因及可追溯证据；若有 commit/PR 再写真实链接，没有就明确未提交。
- 定期回看 `active/` 的阻塞与遗留任务；`completed/` 保留审计索引，不自动加载，也不作为架构事实源。

## 接手顺序

读根入口 → 当前任务卡 → 确认 `git status`/暂存与未暂存 → 按卡片路径核实最新代码 → 继续。
代码可能已被别人改动，任务卡不是锁；不恢复别人的文件以匹配旧卡。
交接必须写下一条可执行步骤和验收缺口，不以“继续完善”结束。

共享任务卡不含密钥、真实用户数据、机器绝对路径；个人笔记与共享工程知识分开。
